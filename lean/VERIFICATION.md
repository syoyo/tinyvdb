## Differential harness: tree structure

`VdbCheck` (Lean model) and `vdbdump` (C reader) are compared on the 13 sample
files by `lean/scripts/diff_vdbdump.py`. Beyond the prologue, descriptors and
grid-body header, the harness now parses the **structured tree** with
`TreeData5.parseFullCount` and compares it against the C reader:

* `Root: N tiles, M children` — root tile and child counts;
* `Nodes: T total (I internal, L leaf)` — node counts (the C reader counts the
  root as total-only, so `I + L + 1 = T`);
* `Active voxels` — the sum of the leaf value-mask popcounts, compared through
  the C reader's `format_count` rendering;
* the tree pass must end exactly at the descriptor's `endOffset`
  (`tree end=… expected=… ok=true`).

The value payload is decoded by a codec stub: the structural pass only needs
the chunk framing (the `i64` size word), which is part of the model. Raw chunks
(`-N`) still have `N` checked against the derived `storedCount * elemSize`, so
a wrong value-count rule is caught.

Coverage: **all 13** files are checked (root tiles/children, internal/leaf
counts, active voxels, exact end offset). All six half grids go through the
proven `TreeData5.parseFullCountH`, in the grid's framing mode: BLOSC/ZIP for
dragon and utahteapot, raw payloads (F14) for cube, bunny and smoke. The
`mode=proven-half framed=...` line records which combination was used.
`Tree_ptdataidx32_5_4_3` is parsed at the topology level only, mirroring the C
reader, which skips point-data buffers and jumps to the grid's end marker; its
node counts and leaf masks still match.

## Differential harness: mask-compression classification

`MaskClassify` (Lean model, `Vdb.MaskCompress.classify`) and the C writer
(`tvdb__write_mask_values`, captured at its classification prefix — the chunk
framing and packed values are not compared, those are covered by the

`lean/scripts/check_mask_classify.sh` over every synthetic 8-slot node:

* all 256 value masks, and for each mask every assignment of the five-symbol

  `sum_j C(8,j) 5^j = 6^8 = 1,679,616` nodes;
* each side prints `mask assign code v0 v1 sel` (the wire code byte 0–6, the
  stored inactive value(s) at full precision as little-endian hex, and the
  selection-mask byte), compared byte-wise;
* coverage is non-vacuous: every code is exercised (code 0: 256 nodes,
  code 1: 255, code 2: 765, code 3: 6050, code 4: 18,150, code 5: 36,300,
  code 6: 1,617,840) and selection bytes range over the full inactive set.

## Differential harness: half-float conversions

`HalfCheck` (Lean model, `Vdb.Half.halfToFloatBits` and
`Vdb.Half.floatToHalfRNE`) and the C encoders (`tvdb__half_to_float`,
`tvdb__float_to_half`) are compared by
`lean/scripts/check_half.sh`:

* `h2f`: all 65,536 half bit patterns, `halfToFloatBits` vs
  `tvdb__half_to_float`, byte-identical dumps;
* `f2h`: one witness per rounding fiber of `float -> half` RNE. The plan
  was a full 2^32 comparison, but the Lean interpreter/compiled code is
  ~4M/s, so the check is structured instead as a fiber comparison: two
  inputs in the same fiber produce the same half, and `HalfCheck`/
  `half_check_c.c` emit exactly one witness per fiber (192,940 cases:
  2,050 Inf/NaN fibers, 224 overflow-to-Inf, 184,320 normal-half fibers
  (`30 exp × 2 sign × 1024 q × 3 residue classes`), ~6k subnormal fibers
  and 204 flush-to-zero fibers). Dumps compare byte-wise;
* the fiber partition itself is machine-validated on the C side by
  `half_check_c.c audit`: it brute-forces all 2^32 inputs and checks
  constancy of the output within every fiber (`audit: 192940 fibers,
  0 mismatches`). The witness count must equal the audited fiber count,
  so no fiber is ever left out of the differential comparison.

Result: **`h2f` 65,536 patterns identical; `f2h` 192,940 witnesses
identical; audit clean over 2^32 inputs.** This harness immediately found
F15 (the exponent-94 scalar-encoder bug above); the Lean model was correct.
The truncating encoder `floatToHalfTrunc` is not compared: the C writer no
longer uses it (F1). The check needs the Lean toolchain and a C11 compiler
only; it is not wired into CTest (run it directly). The audit takes ~16 s.

The model fixes that this harness forced: internal-node children carry **no**
serialized origins (only the root's children do), and half grids omit the value
chunk when the stored count is zero. The earlier model wrote and read `i32 x3`
origins at every level and always framed a chunk, neither of which matches a
real file.
