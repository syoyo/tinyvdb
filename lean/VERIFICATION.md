## Differential harness: tree structure

`VdbCheck` (Lean model) and `vdbdump` (C reader) are compared on the 13 sample
files by `lean/scripts/diff_vdbdump.py`. Beyond the prologue, descriptors and
grid-body header, the harness now parses the **structured tree** with
`TreeData5.parseFullCount` and compares it against the C reader:

* `Root: N tiles, M children` — root tile and child counts;
* `Nodes: T total (I internal, L leaf)` — node counts (the C reader counts the
  root as total-only, so `I + L + 1 = T`);
* `Active voxels` — the sum of the leaf value-mask popcounts, compared through
  the C reader's `format_count` rendering;
* the tree pass must end exactly at the descriptor's `endOffset`
  (`tree end=… expected=… ok=true`).

The value payload is decoded by a codec stub: the structural pass only needs
the chunk framing (the `i64` size word), which is part of the model. Raw chunks
(`-N`) still have `N` checked against the derived `storedCount * elemSize`, so
a wrong value-count rule is caught.

Coverage: **all 13** files are checked (root tiles/children, internal/leaf
counts, active voxels, exact end offset). All six half grids go through the
proven `TreeData5.parseFullCountH`, in the grid's framing mode: BLOSC/ZIP for
dragon and utahteapot, raw payloads (F14) for cube, bunny and smoke. The
`mode=proven-half framed=...` line records which combination was used.
`Tree_ptdataidx32_5_4_3` is parsed at the topology level only, mirroring the C
reader, which skips point-data buffers and jumps to the grid's end marker; its
node counts and leaf masks still match.

## Differential harness: half-float conversions

`HalfCheck` (Lean model, `Vdb.Half.halfToFloatBits` and
`Vdb.Half.floatToHalfRNE`) and the C encoders (`tvdb__half_to_float`,
`tvdb__float_to_half`) are compared by
`lean/scripts/check_half.sh`:

* `h2f`: all 65,536 half bit patterns, `halfToFloatBits` vs
  `tvdb__half_to_float`, byte-identical dumps;
* `f2h`: one witness per rounding fiber of `float -> half` RNE. The plan
  was a full 2^32 comparison, but the Lean interpreter/compiled code is
  ~4M/s, so the check is structured instead as a fiber comparison: two
  inputs in the same fiber produce the same half, and `HalfCheck`/
  `half_check_c.c` emit exactly one witness per fiber (192,940 cases:
  2,050 Inf/NaN fibers, 224 overflow-to-Inf, 184,320 normal-half fibers
  (`30 exp × 2 sign × 1024 q × 3 residue classes`), ~6k subnormal fibers
  and 204 flush-to-zero fibers). Dumps compare byte-wise;
* the fiber partition itself is machine-validated on the C side by
  `half_check_c.c audit`: it brute-forces all 2^32 inputs and checks
  constancy of the output within every fiber (`audit: 192940 fibers,
  0 mismatches`). The witness count must equal the audited fiber count,
  so no fiber is ever left out of the differential comparison.

Result: **`h2f` 65,536 patterns identical; `f2h` 192,940 witnesses
identical; audit clean over 2^32 inputs.** This harness immediately found
F15 (the exponent-94 scalar-encoder bug above); the Lean model was correct.
The truncating encoder `floatToHalfTrunc` is not compared: the C writer no
longer uses it (F1). The check needs the Lean toolchain and a C11 compiler
only; it is not wired into CTest (run it directly). The audit takes ~16 s.

The model fixes that this harness forced: internal-node children carry **no**
serialized origins (only the root's children do), and half grids omit the value
chunk when the stored count is zero. The earlier model wrote and read `i32 x3`
origins at every level and always framed a chunk, neither of which matches a
real file.

## Machine-checked counterexample: the unweighted vertex pseudo-normal (F16)

`Vdb/PseudoNormal.lean` is not a differential harness — it is a
**machine-checked counterexample to the F11 sign-rule fix for vertex
features**. The F11 fix (`mesh_pseudo_normal` in
`src/tinyvdb_mesh_conversion.inl`) sums the unit face normals of the faces
incident on the closest feature (vertex: all incident faces; edge: the two
edge faces; face interior: the face normal) and `mesh_fill_rows` maps a
negative `direction` to "inside".

The counterexample is a rational-coordinate convex tetrahedron: apex at the
origin with outward unit normals `n₁ = (1, 0, 0)`, `n₂ = (−2/3, 2/3, 1/3)`,
`n₃ = (−2/3, −2/3, 1/3)` (all unit) and base `z = −1`. For any `t > 0` the
point `p = t·n₁` is outside (it violates face 1), the apex is its closest
point (every feasible `v` has `x ≤ 0`, so `dist v p ≥ t`), the tight faces at
the apex are exactly faces 1–3, and the unweighted pseudo-normal
`ν = n₁ + n₂ + n₃ = (−1/3, 0, 2/3)` satisfies `⟨ν, p − q⟩ = −t/3 < 0`. So the
"outside ⟺ direction ≥ 0" rule misclassifies an outside point as inside —
on a closed, oriented, *convex* mesh, and `p` is not a knife-edge: the set of
mis-signed outside points is the open cone `{v ∈ cone(n₁, n₂, n₃) : ⟨ν, v⟩ < 0}`,
which contains a full neighbourhood of the `n₁` ray inside the normal cone.

The finding was also reproduced end-to-end through the real C API
(`tvdb_mesh_to_sdf_ex`, single-threaded, not tracked in the repo — a /tmp
diagnostic): the generated dense SDF assigns the outside voxel at
`(0.15, −0.05, 0.05)` the value `v = −0.166` (its distance to the apex —
the closest-feature query and the BVH are correct; only the sign is wrong).
**Resolution**: fixed in C — vertex features now take the maximum pairing
over incident faces (`mesh_feature_direction`), mirrored in the three GPU
kernels and in the mesh→SDF differential twin; the C regression test
`tests/test_mesh_vertex_sign.c` fails on the old code with exactly the two
mis-signed voxels `(0.10, 0, 0)` and `(0.20, 0, 0)` and passes with the fix.
See the F16 row in the findings table.

What is proved vs. not:
* face-interior features: sound (the pairing is `λ·|n| ≥ 0`);
* edge features: the factoring identity `⟨nₐ + n_b, λₐnₐ + λ_b n_b⟩ = (λₐ + λ_b)(1 + ⟨nₐ, n_b⟩)`
  and its unit-normal nonnegativity (`edge_pairing_identity`,
  `edge_pairing_nonneg`); the closest-point cone characterization is now
  formalised in its **usable sign form** (`Vdb/NormalCone.lean`):
  `proj_inner_le_zero_of_admissible` (`⟪p − q, y⟫ ≤ 0` for every direction
  `y` not violating a tight constraint — via the Hilbert projection theorem
  and `norm_eq_iInf_iff_real_inner_le_zero`), which yields the outside-sign
  dichotomy `exists_tight_pairing_pos` and the inside-sign half
  `inside_inner_le_zero` — the convex-case soundness of the fixed sign
  rule; the exact cone expansion (`p − q = Σ λᵢ nᵢ`, λᵢ ≥ 0) is now formalised
  in `Vdb/ConeClosed.lean` (`farkas_closest_direction_exact`) and consumed by
  the VS-4a angle-weighted theorem;
* vertex features: unsound (the counterexample);
* angle-weighted (Bærentzen–Aanæs) pseudo-normals: now modelled in the F16
  instance — `Vdb/AnglePseudoNormal.lean` computes the corner angles
  (`arccos (3/5)`, `arccos (4/5)`, `arccos (4/5)`) and shows the
  angle-weighted apex normal pairs strictly positively at the trap point;
  the general convex case is now proved conditional on the named per-face
  seam `hface`, and unconditionally for non-obtuse normals and the two-face
  planar vertex figure (VS-4a);
* the BVH path, `mesh_triangle_double`, and the CUDA/Vulkan kernels: not
  modelled.

Scope note: F11 as originally landed was sound at face-interior features
(unconditionally) and at edge features of convex polyhedra (modulo the
